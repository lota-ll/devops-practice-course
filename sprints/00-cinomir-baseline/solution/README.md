# cinomir — еталон Спринту 00

Повний робочий код до [завдань спринту](../README.md). Відкривай після власної спроби і порівнюй рішення, а не копіюй.

Вміст цієї директорії = корінь репозиторію `cinomir` (разом з `.github/`, `.env.example`, `.dockerignore`, `.pre-commit-config.yaml`).

## Запуск

```bash
make install                      # .venv + залежності + pre-commit
make test                         # 58 тестів: SQLite + fakeredis, без Docker і без мережі
make up                           # postgres, redis, migrate, api, worker
make search Q="тунець у власному соку"
make search Q="тунець у власному соку" ARGS="--sort unit"

# бот: впиши TELEGRAM_BOT_TOKEN у .env
make up-bot                       # напиши боту — він відповість твоїм id
# впиши id в ALLOWED_USER_IDS у .env
make up-bot
```

API: <http://localhost:8000/docs> · метрики: `/metrics` (api), порт 9100 (worker), 9102 (bot).

```
├── botfmt.py        # форматування повідомлень і кнопок (без Telegram)
├── bot.py           # aiogram: allowlist, пошук, сторінки

tests/               # samples.py — зразки відповідей мереж і фейковий транспорт
```

## Чому саме так

| Рішення | Чому | Альтернатива і чому ні |
|---|---|---|
| В мережу — лише головне слово, фільтр — у нас | Фора шукає за збігом усіх слів (6 результатів замість 37), Сільпо — занадто широко | Повний запит: різна якість по мережах |
| `search_id` з конфігурацією магазинів | Інший магазин = інші ціни = інший кеш | Лише запит: після зміни `FORA_FILIAL` кеш віддасть чужі ціни |
| Не кешувати, якщо впали всі мережі | Інакше 30 хв порожніх відповідей | — |
| Штрихкоди Сільпо — воркер | Окремий запит на кожен товар; у пошуку — +20 запитів і секунди очікування | Синхронно: повільно і агресивно щодо мережі |
| `ean_checked_at` | Товар без штрихкоду не перевіряти щоразу (раз на 7 днів) | Redis-ключ з TTL: губиться при перезапуску Redis |
| Зіставлення union-find | Сільпо↔Фора за id, Фора↔Novus — лише через штрихкод Сільпо: транзитивність | Попарне порівняння: пропускає ланцюжки |
| Ціна за кг лише для сортування | Користувачу потрібні ціна і вага; ціна за кг — для «вигідніше за вагою» | — |
| Таймаут httpx = таймаут мережі + 1 с | Спрацьовує `wait_for` → зрозуміле «не відповіла вчасно» | Однакові: інколи `ConnectTimeout` |
| `NullPool` для SQLite у тестах | aiosqlite + спільне з'єднання між корутинами = `database is locked` | — |
| Бот через API, а не напряму в сервіс | Бот — тонкий клієнт; у спринті 03 він перейде на webhook, а API лишиться | Монолітний бот: не масштабується незалежно |
| `--no-access-log` в uvicorn | Запити логуються middleware у JSON; access log дублює їх рядком тексту | — |

## Що перевірено, а що ні (10.11.2026)

| Перевірка | Результат |
|---|---|
| `ruff check`, `ruff format --check` | ✅ |
| `pytest` (58 тестів) | ✅ |
| Alembic `upgrade → check → downgrade → upgrade` на **PostgreSQL 16** | ✅ (у CI — PostgreSQL 17) |
| Наскрізно: PostgreSQL + Redis + api + worker + фейкові API мереж | ✅ пошук, кеш, збереження 7 товарів, воркер знайшов штрихкод і поширив його на Фору, Novus приєднався до групи, SIGTERM → `worker stopped` |
| Живі API Сільпо / Фори / Novus | ⚠️ лише в spike з твого домашнього IP; з робочого середовища, де писався еталон, мережі недоступні |
| `docker build` і `docker compose up` | ⚠️ не виконано: у середовищі, де писався еталон, заблоковано Docker Hub. `docker compose config` — валідний. Перший `make up` — частина твоєї роботи |
| Бот у справжньому Telegram | ⚠️ потрібен твій токен; форматування і кнопки покриті тестами |
| GitHub Actions workflow | ⚠️ YAML валідний; запуск — після push у твій репозиторій |

Якщо щось з ⚠️ не працює — це гарний матеріал для `docs/notes/sprint-00.md`.
