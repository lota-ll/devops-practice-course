# Шаблон модуля спринту

Кожен спринт — директорія `sprints/NN-назва/`:

```
sprints/NN-назва/
├── README.md     # завдання — читаєш першим
├── hints.md      # підказки, без готового коду — коли застряг
└── solution/     # повний робочий еталон — після власної спроби
    └── README.md # як запустити еталон і чому рішення саме такі
```

## Структура `README.md`

```markdown
# Спринт NN: Назва

> **Сценарій:** бізнес-задача 2–3 реченнями
> **Чому зараз:** місце в roadmap + вага на ринку
> **Вхідний рівень:** що вже маєш вміти
> **Результат:** конкретний, перевірюваний
> **Час:** теорія ~X год · практика ~Y год · break-it ~Z год
> **Вартість AWS:** $0 / ~$N (з інструкцією cleanup)

## Зміст

## 📚 Мінімум теорії (≤ 30%)
Лише концепції, без яких не прийняти рішення. Аналогія → пояснення → де трапиться в практиці.
Один первинний ресурс на тему.

## 🔨 Задачі
### Задача N (X год): назва
> 💡 **Навіщо:** реальний use case
Постановка · обмеження · scaffold (якщо потрібен)
✅ **Перевірка:** команда та очікуваний результат
> 🔑 Підказки: [hints.md#задача-n](hints.md#задача-n) · Еталон: [solution/...](solution/...)

## 💥 Break-it drills
Навмисні поломки: що зламати → що має статися → як діагностувати.

## ⚠️ Типові помилки
| Симптом | Причина | Фікс |

## 📦 Definition of Done
- [ ] чекліст артефактів
**GitHub deliverable:** що має бути в репозиторії

## 🎤 Interview Prep
| Питання | Де ти це робив | Ключові слова |
Історія STAR зі спринту · питання, які задати інтерв'юеру

## ➡️ Що далі
Як результат спринту використовується в наступних
```
